# 架构与工具

## 组件边界

| 组件 | 主要文件 | 职责 |
| --- | --- | --- |
| 侧栏 | `extension/sidepanel.html`、`workspace.js` | 会话、模型与 Agent、消息流、问答和权限确认 |
| 扩展后台 | `extension/background-v2.js` | 配对、本机连接、可信侧栏消息及调试事件 |
| 任务管理 | `task-manager.js`、`group-manager.js` | 按会话和标签隔离、同页队列、临时分组与清理 |
| 页面驱动 | `page-agent.js`、`frame-driver.js`、`action-driver.js` | 结构读取、稳定引用、动作、输入验证 |
| 指针 | `extension/overlay.js` | 网页内容区覆盖层，不移动 Windows 系统鼠标 |
| 本机组件 | `native-host.mjs`、`native-*.mjs` | Chrome Native Messaging、受限的本机会话 API、事件投影 |
| MCP | `server.mjs` | stdio 工具入口、认证 WebSocket 桥接与多实例复用 |
| 生命周期 | `opencode-plugin/index.mjs` | 订阅 OpenCode 事件，按所有者和时间清理任务 |
| UI 构建 | `ui/`、`build-ui.mjs` | 打包本地 Markdown、净化器、高亮和流式状态模块 |

## MCP 工具

工具由 OpenCode 暴露，实际调用名称以当前工具目录为准。

| 工具 | 用途 |
| --- | --- |
| `list_tabs` | 列出普通网页标签，省略 URL 查询参数和 fragment |
| `begin_task` | 用任务简要开始任务；可指定一个 `tabId` 或最多 8 个 `tabIds` |
| `select_tab` | 增加／选择任务页面，不释放其他已持有页面 |
| `get_status` | 查看当前任务页面、其他锁定页面和接管状态 |
| `inspect` | 读取指定页及可访问框架、Shadow DOM，返回短引用 |
| `highlight` | 高亮一个目标，不点击 |
| `click` | 派发点击并提供可视反馈，不把输入成功当作业务成功 |
| `type_text` | 替换文字并验证值；不提交表单，拒绝可识别的密码／支付字段 |
| `scroll` | 滚动指定页面／框架 |
| `wait_for` | 只读等待 URL、文字或元素条件，不重试输入 |
| `end_task` | 结束任务，移除指针并恢复所有受控页的原分组 |
| `release` | 结束任务的别名 |

推荐生命周期：

```text
list_tabs（需要确认目标时）
begin_task(summary="对比两个页面", tabIds=[123, 456])
  ├─ inspect(tabId=123)
  └─ inspect(tabId=456)        ← 不同页可并行
使用各页新鲜 ref 或明确 tabId 执行用户授权的动作
wait_for / inspect 验证结果
end_task                     ← 成功、失败或取消都要清理
```

本项目未提供通过浏览器地址栏任意打开／导航 URL 的专门工具；优先操作已打开且明确选定的页面。不要把已有工具之外的能力描述成已经实现。

## 引用与动作正确性

- 引用绑定标签、具体 `documentId`、DOM 节点和语义指纹。
- 同一页重新检查、节点替换或文档变化会使旧引用失效。
- 不同页的引用互不清除；使用 ref 的动作自动路由回原标签。
- 角色／名称或 CSS 定位必须唯一，歧义、遮挡和持续移动的目标不会被强行点击。
- 主文档使用 CDP 输入；子框架使用 DOM activation／原生 value setter，因此不是所有站点都接受子框架输入。
- 点击返回“已派发”后，必须检查实际结果；发生超时或跳转时不能盲目重复动作。

## 并发与分组

同页操作串行，不同页独立排队。任务所有者来自 OpenCode MCP 元数据中的会话 ID；没有元数据的客户端使用实例级标识。

同一个页面不能由两个任务同时持有。任务结束会先使旧动作失效，再移除覆盖层和分组；已派发操作仍在结束的页面保留排空锁，避免立即交给另一个任务。

同一任务在同一窗口共享一个任务组，跨窗口使用同名组。未分组页面结束后恢复未分组；用户原分组会尽量恢复。用户手动把页面移到另一组后，清理不会覆盖该新选择。

## 清理机制

1. 模型在任务结束前调用 `end_task`。
2. OpenCode 插件监听执行完成、失败、中断及会话删除，按会话所有者及事件时间清理，避免旧完成事件终止新任务。
3. MCP 请求取消或超时会触发对应任务的停止／清理，不取消无关页面任务。
4. 超过 5 分钟无浏览器动作且没有执行中的工具，会在分钟检查时兜底释放。

浏览器或扩展被强制结束、完整重启时不保证所有分组清理均能执行。兜底超时也不是对模型“思考完成”的判断。

## 本机通信

- stdio 用于 OpenCode 与 MCP；WebSocket 默认仅监听 `127.0.0.1:17891`。
- 当前协议为 **4**，扩展与桥接版本必须匹配。
- 配对凭据按本机生成，不随代码分发。
- Native Messaging 调用受 Chrome 的 `allowed_origins` 和本机入口双重来源检查限制。
- 侧栏只开放固定会话操作，认证服务头由本机组件处理，不传给网页。
- 主桥接退出会中断连接；需要重连及人工恢复，不承诺跨进程故障无缝执行。

更详细的风险说明见 [权限与隐私](SECURITY.md)。
